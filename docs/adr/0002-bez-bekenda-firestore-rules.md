# 0002 — Без бекенда; безбедност кроз Firestore rules

**Статус:** Прихваћен

## Контекст

Принцип доступности захтева нулте трошкове покретања и одржавања. Апликацију користи мали тим, без јавне регистрације.

## Одлука

Нема сопственог сервера. Фронтенд је статички (GitHub Pages), а подаци су у Cloud Firestore-у и Firebase Storage-у. Аутентификација је Google Sign-In. Приступ се одређује whitelist-ом (колекција `allowedUsers`, ID документа је email). Права (Admin: пуна контрола, Viewer: само читање) спроводе се искључиво у `firestore.rules` и `storage.rules`; клијентска провера је само UX. Правила се тестирају у `rules-tests/`.

## Последице

- Нула трошкова сервера и једноставан деплој (`npm run deploy`).
- Firebase Web API кључ је јаван по дизајну; заштиту дају правила, па су она извор истине за безбедност и морају имати тестове.
- Whitelist се мења ручно кроз Firebase конзолу (нема Admin UI-а).
- Агрегације (салдо, дашборд) рачунају се на клијенту, што ограничава скалу на мале количине података.
- Сложена валидација која не може у rules језику није могућа без бекенда.
